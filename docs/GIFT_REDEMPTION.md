# CDK 与公共口令第一版候选

后台“礼包兑换”独立于角色选择，支持批量随机 CDK、公共口令、单种物品邮件奖励、活动编号、结束时间、停用与最近 1000 条领取记录。随机 CDK 每码一次，公共口令可设置总额度；同一活动每账号一次。完整码仅生成时返回，数据库保留摘要及前缀。

玩家先通过登录器登录并启动游戏，再打开“礼包兑换”，选择当前登录账号的角色。登录令牌仅保存在 Host 内存，由网关查询服务端账号令牌表验证；角色归属由服务端校验。登录器重启后需要重新登录。

额度受理和领取记录使用数据库事务；已受理记录固定账号和角色。邮件通过既有资产事务及永久回执发放；网络中断可用原码、原角色重试。停用阻止新领取，已受理发放仍可重试。跨库不采用单一事务，待发放记录保留额度并用于恢复。

部署前必须执行 `--init-management-schema` 创建独立礼包表，然后重新构建网关、GM Console 与登录器。现有游戏服基础兑换模块没有直接装配到邮件链路，本候选在网关复用实际邮件仓储。尚未自动发布二进制或修改线上数据库。

开发验证已补齐临时 Go 1.26.5、npm 和 .NET 8 SDK：GM Console 类型检查和生产构建通过，既有 166 项测试通过，并新增礼包表单独立渲染测试；网关、管理装配和礼包接口编译通过，礼包参数及鉴权专项测试、受影响包 `go vet` 通过；登录器 Engine、Host 使用隔离配置编译通过，Core 155 项安全检查与 Portable 14 项检查通过。

EngineTests 的旧 QQ 绑定断言已按注册码迁移约定更新：旧配置不能重新启用绑定入口或强制绑定。新登录开始时清除旧礼包令牌，防止新登录失败后仍以旧账号兑换；另补充未登录时拒绝角色查询和兑换的专项检查。最终整套运行通过，输出为 1100 项检查（其中诊断采样检查数量随运行变化）。

`TestGiftMySQLConcurrentAllowanceAndReplay` 已在独立临时 MySQL 8.4 实例实际通过，覆盖 20 并发请求限领 3 份、停用后的受理重试、角色切换拒绝、回执重放、同活动多码限领、随机 CDK 单次使用和令牌过期拒绝。既有邮件晚失败回滚与永久回执重放的两项 MySQL 测试也通过。测试库由测试创建和移除，临时数据库实例已关闭，没有连接现有业务数据。

网关整包测试曾长时间未结束而中止，不能宣称整包回归通过。Flutter SDK 官方域名解析失败，社区镜像未取得文件，Flutter analyze/test、浏览器交互和真机验收尚未完成。此状态不能作为生产发布依据。

验收重点：随机码只能领取一次；同活动不同码不能重复领；公共口令多账号并发遵守总额度；过期/停用/外账号角色拒绝；并发重试和邮件提交后断线不重复发奖；数据库不可用时不放行；重启后待发放记录可恢复。
